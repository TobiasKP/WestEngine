● The issue is the Lua stack is unbalanced after the break in the world branch.
  Let me trace it:

  Normal property flow: After the inner lua_next loop finishes (returns 0), the
  last key is auto-popped. Stack: T, K, V. Then lua_pop(L, 1) pops V → T, K.
  Outer lua_next(L, -2) finds T at -2. Works.

  World/break flow: After createWorld + lua_pop(L, 1), stack is T, K, V, 
  "world". Break exits. lua_pop(L, 1) pops "world" → T, K, V. Outer lua_next(L, 
  -2) finds K at -2 — not a table → segfault.

  The fix: pop both the value and the key before breaking, so the post-loop
  lua_pop(L, 1) correctly pops V.

● Here's the full performance analysis:

  ---
  Performance Analysis

  CRITICAL

  1. Scene::getEntities() copies the entire entity vector every frame
  - Called in both RenderManager::renderGameEntities() and
  ShaderManager::update()
  - Copies every Entity including its unordered_map<uint16_t, IComponent*>
  components
  - For N entities, that's N map copies + vector allocation per frame
  - Fix: Return const std::vector<Entity>& or provide iterator access under lock

  2. PoolAllocator is not thread-safe
  - Entity::operator new uses the pool allocator, but the free-list manipulation
   has no synchronization
  - Multiple threads creating entities = memory corruption
  - Fix: Add a mutex or use thread-local allocators

  3. Scene race condition
  - getEntities() copies under lock, but _debugEntities is accessed outside the
  lock
  - During iteration in render, another thread could addEntity() causing vector
  reallocation
  - Fix: Extend lock scope or use a double-buffer pattern

  HIGH

  4. No shader/material batching in render loop
  - Entities rendered in arbitrary order, causing unnecessary glUseProgram() and
   texture bind switches
  - The TODO at Scene.cpp:81 acknowledges this
  - Fix: Sort entities by shader group before rendering

  5. UI buffer recreation every frame
  - renderUserInterfaces() creates 4 vectors, fills them element-by-element,
  then uploads with glBufferData(GL_STATIC_DRAW) every frame
  - Fix: Use GL_STREAM_DRAW and persistent mapped buffers, or glBufferSubData()

  6. Per-entity uniform updates with no dirty tracking
  - Transformation matrix recalculated every frame even if entity hasn't moved
  - Material color uniform re-uploaded even if unchanged
  - Fix: Add dirty flags to Position and Material components

  MEDIUM

  7. Entity ID lookup is O(n) linear search (Scene::getEntityById)
  - Acknowledged by the TODO at Scene.h:30
  - Fix: Add unordered_map<uint32_t, size_t> mapping ID to vector index

  8. Sequential manager execution
  - All 7 managers run sequentially in iterateQ(). InputManager, SystemManager,
  and InterfaceManager could run in parallel
  - Fix: Identify independent managers and parallelize

  9. Redundant uniform creation per entity
  - ShaderManager::addUniforms() calls glGetUniformLocation for every entity
  even when they share the same shader program
  - Fix: Cache uniform locations per program, not per entity

  10. Pause loop burns 100% CPU
  - while (Config::PAUSE) with no sleep
  - Fix: Add std::this_thread::sleep_for() or wait on condition variable

  LOW

  11. OBJ parsing uses repeated strncmp/sscanf per line — fine for load-time but
   could use memory-mapped I/O for large models

  12. No frustum culling — all entities drawn regardless of visibility

  13. Entity::_components uses unordered_map — overhead for typically 2-4
  components per entity. A small fixed array indexed by component bit position
  would be faster and more cache-friendly

  ---
  The biggest wins would be #1 (stop copying the entity vector every frame) and
  #4 (batch by shader group). Those two alone would significantly reduce
  per-frame allocations and GL state changes.
