● The import is red because WestRenderer is never linked into the core target,
  so its public include directory is never propagated to the compiler.

  Here's the chain:

  - WestRenderer/CMakeLists.txt:23-29 exposes its header folder as a PUBLIC
  include ($<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}>). That's the only way
  <WestRendererFacade.hpp> (angle-bracket include) becomes findable.
  - That include path only reaches a consumer that links against WestRenderer.
  - But WestEngine/CMakeLists.txt:50-60 links WestUtils, WestInterface, WestData
  — not WestRenderer. So the core module never gets the include dir, and
  #include <WestRendererFacade.hpp> can't be resolved → red.

  That's why WestData/WestInterface facades resolve fine but the renderer one
  doesn't — they're in the link list, it isn't.

  The fix is one line:

  target_link_libraries(${PROJECT_NAME}
      PRIVATE
      WestUtils
      WestInterface
      WestData
      WestRenderer      # <-- add this
      GLEW::GLEW
      ...
